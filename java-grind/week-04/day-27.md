# Day 27 — Git: Tags, .gitignore & Best Practices
**Phase 2 · Week 4 · Saturday**

---

## Goals
- Use tags to mark meaningful points in your history
- Write a proper `.gitignore` so you stop committing IDE files and build artifacts
- Solidify commit hygiene: small, focused, well-named commits

---

## Tasks
1. Add a proper `.gitignore` to all your repos — use gitignore.io for Java + Maven + IntelliJ
2. Check `git status` — are files tracked that shouldn't be? Remove them with `git rm --cached`
3. Tag your Library System as `v1.0` using an annotated tag (`git tag -a`)
4. Push your tag to GitHub — find it under "Releases"
5. Audit your commit history honestly — would someone else understand every message?

---

## Challenge
Look up `git stash`. Use it: make some changes, stash them, do something else, pop the stash. Understand what it's for and when you'd use it instead of a branch.
